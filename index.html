Financial Control API

RepositórioRepository

Problema: Controle financeiro pessoal em planilha não escala e não impõe nenhuma disciplina de modelagem.

Problem: Personal finance tracked in spreadsheets doesn't scale and enforces no data modeling discipline.

Resultado: API com seis domínios completos (autenticação, contas, categorias, transações/transferências, orçamentos e relatórios), implantada na AWS com Terraform: VPC em duas zonas de disponibilidade, RDS privado, ALB e ECS Fargate. Deploy automatizado por GitHub Actions com OIDC, sem chaves de longa duração armazenadas. Repositório público, incluindo o histórico de decisões técnicas do planejamento.

Result: API with six complete domains (auth, accounts, categories, transactions/transfers, budgets, and reports), deployed to AWS with Terraform: a two-AZ VPC, private RDS, ALB, and ECS Fargate. Deployment is automated through GitHub Actions with OIDC, with no long-lived keys stored. Public repo, including the planning history and technical decisions.

NestJS PostgreSQL AWS (ECS Fargate) Terraform GitHub Actions (OIDC)

Flight Price Tracker

RepositórioRepository

Problema: Acompanhar preço de passagem aérea manualmente é repetitivo, e a queda de preço passa despercebida.

Problem: Manually tracking flight prices is repetitive, and price drops go unnoticed.

Resultado: Robô que roda diariamente via GitHub Actions, sem servidor próprio. Monitora rotas configuráveis em YAML e alerta por e-mail quando o preço cai abaixo do valor-alvo, com histórico versionado em SQLite. Construído com TDD desde o planejamento, com spec e plano aprovados antes do código: 98 testes, 96% de cobertura, ruff e mypy --strict em CI. A transação é atômica com rollback; se o envio de e-mail falha, nada é gravado no banco.

Result: A bot that runs daily via GitHub Actions, with no server of its own. It monitors YAML-configured routes and emails an alert when the price drops below target, with price history versioned in SQLite. Built test-first from a written spec and plan: 98 tests, 96% coverage, ruff and mypy --strict in CI. The transaction is atomic with rollback; if the email fails, nothing gets written to the database.

Python 3.12 SQLite SerpApi GitHub Actions smtplib
